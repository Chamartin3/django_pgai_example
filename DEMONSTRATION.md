## Tracking vectorizer progress

The example ships with two ways to monitor embedding progress while the
`vectorizer-worker` is running.

**Django admin** — the plugin registers a `Vectorizer` admin view with
state badges (`queued` / `active` / `done`), progress bars, pending counts,
and source/embedding-store columns. Enable in `INSTALLED_APPS` via the
plugin's `register_admin` opt-in.

![Django admin: vectorizer list](docs/images/admin-vectorizers.png)

**`pgai list` command** — terminal view from the plugin with per-vectorizer
state, throughput (chunks/s), batch size, and ETA. Run it to watch a backfill
complete:

```bash
./manage.sh pgai list
```

![pgai list terminal output](docs/images/pgai-list.png)

Use either one to confirm all four vectorizers reach `done` before running
the queries below — partial vectorization will skew the comparison.

## Reading the report

- **All variants agree on top hit** → the result is robust. Safe to raise `--threshold` to suppress weak matches.
- **Partial agreement** → take the majority pick but inspect the dissenter — it may be reacting to a different facet (mood vs. plot, etc.).
- **Each variant returns different titles** → query is semantically ambiguous. Try `--rank-by relevance` to weight by per-hit match count, or rephrase.
- **Fastest variant**: pick for online queries (chat UI, autocomplete). 
- **Most accurate variant** (highest top-1 scores, agreement): pick for offline batch ranking.
